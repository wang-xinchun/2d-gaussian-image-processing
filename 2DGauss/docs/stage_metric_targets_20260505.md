# V1 阶段性指标目标

更新时间: 2026-05-05

## 文档定位

这份文档用于给当前 `2DGauss` 项目设定一个可执行、可汇报、可持续追踪的阶段性指标目标。

这里的目标不是直接照搬某篇论文里的 SOTA 数字，而是结合两类事实共同设定：

1. 顶刊顶会图像复原论文的主流评估口径。
2. 我们当前已经跑出的本地有效基线。

特别说明：

- `UHD-LL_down4`、`UHD_haze`、`UHD_deblur` 并不是都已经完成了与公开论文完全同协议的对比复测。
- 因此，本文件给出的不是“已经确认的文献 SOTA 门槛”，而是“符合顶会论文习惯的阶段性目标体系”。
- 这样做的目的，是让我们现在就能有明确目标，同时避免伪造一个并未真正核实过的绝对对比数值。

## 一、顶刊顶会常见指标口径

结合当前已整理的顶会论文和研究报告，当前主流 restoration 工作的指标口径可以概括为：

1. 经典配对复原任务，通常以 `PSNR` 和 `SSIM` 作为主指标。
2. 真实场景复原任务，除了 `PSNR`、`SSIM`，常常还会补 `LPIPS` 评价感知质量。
3. 若任务偏真实退化、真实观感或无参考质量，也会进一步补 `NIQE` 等指标。

对我们当前项目来说，最合适的落地方式是：

- 当前短训阶段的硬门槛指标先用 `PSNR`。
- 后续正式结果表和汇报图，至少补齐 `SSIM`。
- 对 `UHD_haze`、`UHD_deblur` 这类真实感知更重要的任务，论文阶段建议再补 `LPIPS`。

原因很简单：我们现阶段已经有稳定的 `PSNR` 记录和历史基线，因此它最适合充当短期推进的硬目标；而 `SSIM/LPIPS` 更适合作为下一步补齐的正式评估项。

## 二、设定目标时采用的统一原则

### 2.1 先看同协议可比性，再看绝对数值

如果训练设置、验证集、test split、crop 策略不一致，那么绝对 dB 数值的解释力会明显下降。
因此当前最重要的是：

- 尽量在同一协议下比较新旧实验；
- 先把 official test 评估闭环补齐；
- 再讨论是否达到“对比论文级别”的数值。

### 2.2 在顶会 restoration 里，稳定的几十分之一到几十分之几 dB 改进就有意义

参考主流 restoration 论文的常见结果呈现方式，在协议一致的前提下，可以采用下面的解释标准：

- `+0.3 dB`：可认为是有意义的真实改进。
- `+0.5 dB`：可认为是比较清楚的阶段性进步。
- `+1.0 dB` 及以上：可认为是很强的提升，通常说明模型或训练策略确实发生了有效变化。

这条标准适合我们后续做内部判断，也适合汇报时解释“为什么这轮实验算推进了”。

### 2.3 当前阶段不要只盯一个数

即使当前以 `PSNR` 为硬目标，也不能只看一个最终 dB：

- 要看是 `validation` 还是 `official test`；
- 要看是否是 full-val 还是小样本 noisy val；
- 要看提升是否稳定，而不是偶然抖动。

因此，现阶段更推荐“主指标 + 评估闭环完整性”的双重目标。

## 三、当前 V1 的阶段性指标目标

| 任务 | 当前有效基线 | 下一阶段硬目标 | 较强目标 | 论文/汇报阶段要求 |
|---|---|---|---|---|
| `UHD-LL_down4` | `A01` official test `PSNR=25.7391 dB` | official test `PSNR >= 26.0 dB` | official test `PSNR >= 26.5 dB`，且 full-val / test 结论一致 | `PSNR + SSIM` 必报；若强调纹理恢复，可补 `LPIPS` 与可视化 |
| `UHD_haze` | `A_a02` step 2000 validation `PSNR=19.9608 dB`，但尚无 official test 完整结论 | 先补齐 official test 评估，并把稳定 validation/full-val `PSNR` 推到 `>= 20.0 dB` | 数据管线优化后，official test `PSNR >= 20.5 dB`，或相对首个有效 official baseline 提升 `>= 0.5 dB` | `PSNR + SSIM` 必报；建议补 `LPIPS`；需要雾浓区域可视化对比 |
| `UHD_deblur` | 暂无有效本地 baseline | `A03` 的第一目标不是追绝对 SOTA，而是先建立可复现的 official baseline | 第一条有效 baseline 建立后，下一轮目标设为同协议 `PSNR +0.5 dB` 以上 | `PSNR + SSIM` 必报；建议补 `LPIPS` 和运动边缘裁剪图 |

## 四、当前最建议采用的“统一汇报口径”

如果现在只给项目定一条最实际、最容易执行的目标，我建议写成下面这句话：

> 当前阶段的核心指标目标是：在保持同一评估协议的前提下，把 `V1` 在已验证任务上的 `official test PSNR` 稳定推进到比当前有效基线高约 `0.5 dB`；具体到 `UHD-LL_down4`，先做到 `PSNR >= 26.0 dB`，具体到 `UHD_haze`，先补齐 official test 评估并把稳定 `PSNR` 推到 `20.0 dB` 以上。

这句话的好处是：

1. 它和顶会论文的主流指标体系一致。
2. 它和我们当前真实已有的实验基线一致。
3. 它既能拿来指导下一轮实验，也能直接拿去汇报。

## 五、怎么解读这套目标

### 5.1 `UHD-LL_down4`

这条线已经有完整 official test 结果，所以它最适合做当前主基线。

因此：

- `25.7391 dB` 是“已经证明可行”的起点。
- `26.0 dB` 是下一阶段合理、克制、可执行的目标。
- `26.5 dB` 则可以视为明显更强的一版结果。

### 5.2 `UHD_haze`

这条线当前的瓶颈不完全在模型，而在数据管线和评估闭环。

因此这里不能直接把 `19.9608 dB` 当成 final paper result 去解释，而应该拆成两个子目标：

1. 先把 evaluation loop 做完整，拿到可信 official test 结果。
2. 再在同协议下把指标提升到 `20.0+`，之后争取 `20.5+`。

这更符合真实研发节奏，也更符合顶会论文对实验严谨性的要求。

### 5.3 `UHD_deblur`

目前还没有第一条有效 baseline，所以不适合现在假装给出一个“论文级绝对阈值”。

对这条线，更合理的目标设计是：

- 第一轮先建立 baseline；
- 第二轮再要求稳定超过 baseline `0.5 dB` 左右。

这比空定一个没有依据的绝对值更可信，也更适合真实推进。

## 六、结论

基于顶刊顶会的主流评价方式，以及我们当前已经拿到的本地实验结果，现阶段最合理的指标目标不是“硬写一个未经核实的文献 SOTA 数字”，而是采用下面这套阶段性标准：

1. 当前硬指标以 `PSNR` 为主。
2. 正式汇报必须逐步补齐 `SSIM`，真实任务建议补 `LPIPS`。
3. `UHD-LL_down4` 近期目标设为 official test `PSNR >= 26.0 dB`。
4. `UHD_haze` 近期目标设为先补齐 official test，再把稳定 `PSNR` 推到 `20.0 dB` 以上。
5. `UHD_deblur` 先建立 baseline，再以 `+0.5 dB` 作为下一轮改进目标。

如果后面我们补齐了 `SSIM/LPIPS` 评估，或者从已下载论文中进一步抽取出与本地数据协议更接近的公开对比数值，这份目标文档可以再升级成更严格的“对比论文版指标目标”。
