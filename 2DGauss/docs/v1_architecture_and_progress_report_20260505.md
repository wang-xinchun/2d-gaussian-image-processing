# V1 模型架构与项目阶段进展汇报

## 文档定位

这份文档用于对当前 `2DGauss` 项目进行一次可直接用于阶段汇报的整理，集中回答以下问题：

1. 我们当前到底在做什么研究问题。
2. 目前的可执行模型 `V1` 是怎样设计的。
3. 为什么要这样设计，而不是直接沿用常规高分辨率复原 backbone。
4. 到目前为止已经完成了哪些训练实验，得到什么结论。
5. 当前项目真正卡在哪里，下一步应该怎么推进。

本文成稿时间为 `2026-05-05`（UTC 环境下整理），但项目状态快照主要依据日志中截至 `2026-04-25 23:33:22 CST` 的有效记录。也就是说，本文反映的是当前仓库里已经有据可查的最新阶段结果，而不是假定后续还有未记录的新实验。

## 一、项目目标与研究问题

### 1.1 投稿目标与项目主题

- 目标期刊：`IEEE Transactions on Image Processing (TIP)`
- 项目主题：`超高清图像复原`
- 当前阶段定位：先验证研究主线与可执行架构是否成立，再进入更强实验与更完整论文化

### 1.2 当前正式研究问题

当前项目聚焦的不是普通分辨率图像复原的小幅性能改进，而是以下问题：

> 在超高清图像复原任务中，如何避免直接在原始分辨率上进行高成本密集建模，同时又不过度牺牲高频纹理、局部结构和精细细节的恢复能力？

这个问题的核心矛盾在于：

1. UHD 图像分辨率高，直接全分辨率 dense 建模代价极大。
2. 常规下采样后再恢复，容易丢失高频纹理和细节。
3. 传统 2D Gaussian 表达更偏几何包络，不足以覆盖复杂纹理模式。
4. 因此我们需要一条中间路线：在低分辨率空间做更紧凑的结构化建模，再把引导信息高效作用回高分辨率图像或特征。

### 1.3 当前一句话方法主线

我们当前正式采用的方向可以概括为：

> 面向超高清图像复原，构建一种跨分辨率、纹理/频率感知的 2D Gaussian 引导框架：先在低分辨率空间预测紧凑的结构化参数场，再通过高分辨率注意力回注与仿射调制机制，把这些信息作用回高分辨率复原过程。

## 二、设计思路与方法动机

### 2.1 为什么不直接做全分辨率 dense restoration

如果直接在原始 UHD 分辨率上堆叠 dense attention、dense feature interaction 或大型高分辨率 backbone，会遇到几个问题：

1. 显存和计算成本快速上升，不利于实际部署和中长程实验。
2. 高分辨率 dense 建模的收益不一定与代价成正比。
3. 对于论文主线来说，单纯“换一个更强 backbone”难以形成清晰的方法贡献。

因此，本项目并不把“再造一个传统复原骨干网络”作为主线，而是把论文叙事放在：

- 低分辨率紧凑参数建模
- 纹理/频率感知的 Gaussian 参数化
- 高分辨率结构化引导回注
- 避免 full-resolution dense attention 的 UHD 友好范式

### 2.2 为什么引入 2D Gaussian

2D Gaussian 的价值不是把它当成传统意义上的几何原子照搬，而是把它扩展成一种结构化、可解释、可跨分辨率传递的局部建模单元：

1. 它天然适合在低分辨率网格上进行紧凑参数化。
2. 它可以显式描述局部位置、尺度、方向等包络信息。
3. 在我们的设计里，它还可以继续扩展为纹理/频率感知原子，而不是只保留几何属性。
4. 这样得到的不是无结构 feature map，而是一组更可控的局部结构化参数。

### 2.3 为什么引入纹理/频率感知

如果仅靠低分辨率语义特征来预测 Gaussian 参数，模型容易偏向平滑结构，而弱化超高清图像里最重要的高频信息。因此我们在低分辨率分支中显式加入纹理/频率描述子，包括：

- 灰度信息
- Sobel x 梯度
- Sobel y 梯度
- 梯度幅值
- Laplacian 响应

这类信息的作用是帮助低分辨率参数头不仅“知道哪里有结构”，还“知道那里是什么样的高频结构”。

### 2.4 为什么使用高分辨率仿射回注

低分辨率参数场不能简单上采样后直接代替高分辨率恢复，因为那样会损失设计主线中的“结构化引导”含义。我们当前采用的思路是：

1. 先由低分辨率 Gaussian 参数渲染出高分辨率标量注意力图。
2. 让这个注意力图优先作用于高分辨率特征中的 high-pass 成分。
3. 再利用低秩仿射调制，在通道维度上对高分辨率特征进行进一步调制。

这样做的目的，是让低分辨率建模结果以“引导”和“调制”的形式回注高分辨率，而不是生硬地替代高分辨率特征本体。

## 三、当前可执行模型：V1 架构

### 3.1 V1 的角色定位

当前仓库中的 `V1` 不是论文最终定稿模型，而是一版满足以下条件的可执行基线：

1. 与研究方向主线一致。
2. 可以稳定前向、训练、记录指标、保存 checkpoint。
3. 便于后续模块替换、做消融、做跨任务验证。
4. 结构尽量清晰，让我们先验证“方向是否成立”，而不是过早陷入复杂工程细节。

### 3.2 当前默认配置

当前模型默认配置如下：

- 输入通道：`3`
- 输出通道：`3`
- 基础宽度：`32`
- 低分辨率缩放因子：`4`
- 高分辨率分支残差块数：`2`
- 低分辨率分支残差块数：`4`
- 解码器残差块数：`2`
- 仿射低秩 rank：`4`
- Gaussian atom 数量：`4`
- 每个 Gaussian atom 参数维数：`10`

在当前配置下，preflight 记录的总参数量为：

```text
total_params = 70223
```

这说明当前 `V1` 是一个非常轻量的可执行架构，其主要价值是验证方法主线，而不是追求最终性能上限。

### 3.3 V1 的整体数据流

当前模型可以用下面的流程概括：

```text
输入图像 x
  -> padding 到 lowres_scale 的整数倍
  -> 高分辨率分支 highres_stem，得到 highres_feature
  -> pixel_unshuffle 到低分辨率空间
  -> 低分辨率投影与残差建模，得到 lowres_feature
  -> 低分辨率 RGB + 显式频率描述子，得到 texture_feature
  -> lowres_feature 与 texture_feature 融合
  -> Gaussian 参数头，预测 gaussian_params 和 affine_coeffs
  -> Gaussian 渲染器，将低分辨率参数渲染为高分辨率 attention_map
  -> 用 attention_map 调制 highres high-pass 特征
  -> 低秩 affine 模块进一步做高分辨率通道调制
  -> 将调制后的高分辨率特征与上采样低分辨率特征拼接
  -> decoder 预测残差 residual
  -> restored = input + residual
```

### 3.4 当前 V1 的模块拆解

#### 3.4.1 高分辨率分支

高分辨率分支由一个 `3x3 Conv` 加若干残差块构成，其职责不是进行极重的全图建模，而是：

1. 保留原始高分辨率图像的局部细节表达。
2. 为后续的 attention 回注与 affine 调制提供宿主特征。
3. 形成最终残差预测的高分辨率基础。

这一分支可以理解为“高分辨率细节容器”。

#### 3.4.2 低分辨率紧凑建模分支

输入图像先经过 `pixel_unshuffle(scale=4)`，把空间分辨率压到更低尺度，并把局部空间邻域折叠到通道维。随后通过 `1x1 Conv + residual blocks` 构建低分辨率特征。

这个分支承担的是：

1. 在较低的空间分辨率上进行更经济的结构化建模。
2. 为 Gaussian 参数预测提供紧凑特征基础。
3. 避免在原图尺度上直接做高成本 dense 建模。

#### 3.4.3 纹理/频率特征提取模块

当前显式频率模块提取以下描述子：

- gray
- `|grad_x|`
- `|grad_y|`
- `grad_mag`
- `|laplacian|`

然后将这些描述子与低分辨率特征拼接，经 `1x1 conv + residual refine` 变换得到 `texture_feature`。

这一模块体现了当前项目非常关键的一点：

> 我们并不希望低分辨率 Gaussian 参数只感知平滑语义，而是希望它对纹理、边缘、方向和高频变化也有直接响应。

#### 3.4.4 Gaussian 参数头

当前 Gaussian 参数头在低分辨率网格上预测两类输出：

1. `gaussian_params`
2. `affine_coeffs`

其中 `gaussian_params` 的形状本质上是：

```text
[B, H_low, W_low, atoms, param_dim]
```

当前 `atoms=4`，`param_dim=10`。这 10 个参数目前对应的是：

1. `amplitude`
2. `mu_x`
3. `mu_y`
4. `sigma_x`
5. `sigma_y`
6. `theta`
7. `texture_gain`
8. `frequency`
9. `phase`
10. `beta`

这表明当前的 Gaussian 原子已经不是传统纯几何高斯，而是包含了纹理载波和频谱衰减信息的纹理感知高斯原子。

#### 3.4.5 Gaussian 渲染器

Gaussian 渲染器的作用是把低分辨率参数场还原成高分辨率引导图。当前它做的事情包括：

1. 根据 `mu / sigma / theta` 构造定向高斯包络。
2. 通过 `texture_gain / frequency / phase` 叠加纹理型载波。
3. 通过 `beta` 控制谱衰减。
4. 将多个原子求和并映射成高分辨率 `attention_map`。

最终得到的是一个单通道高分辨率标量引导图，用来引导高分辨率特征增强。

#### 3.4.6 高分辨率 high-pass 调制

当前模型没有直接对高分辨率特征做大规模 dense attention，而是先构造：

```text
highpass = highres_feature - avg_pool(highres_feature)
```

然后执行：

```text
modulated = highres_feature + attention_map * highpass
```

这个设计的含义是：

1. 模型重点增强高频残差信号，而不是整体特征都被同样调制。
2. 低分辨率参数渲染出来的 attention 更聚焦于结构和细节恢复。
3. 这种方式比 full-resolution dense attention 更轻量，也更符合当前方法主线。

#### 3.4.7 低秩仿射调制模块

在高频增强之后，模型还会执行一个低秩 affine modulation：

1. 先在低分辨率预测 `rank=4` 个仿射系数图。
2. 上采样到高分辨率。
3. 通过 `scale_basis` 和 `bias_basis` 组合成高分辨率通道尺度项与偏置项。
4. 最终执行：

```text
features * (1 + scale) + bias
```

这一模块的意义在于：

- 不直接预测完整高分辨率仿射参数，降低参数量与显存压力。
- 让低分辨率紧凑参数场能够继续在通道层面对高分辨率特征产生可学习影响。

#### 3.4.8 解码器与残差输出

最后一步将：

- affine 调制后的高分辨率特征
- 上采样回来的低分辨率融合特征

在通道维拼接，再通过解码器输出残差 `residual`，最终得到：

```text
restored = input + residual
```

这种 residual learning 形式适合大部分配对图像复原任务，也使 `V1/T01` 能方便迁移到低照度、去雾、去模糊等同分辨率复原设置。

### 3.5 当前 V1 架构的特点

#### 优势

1. 架构清晰，和论文主线高度一致。
2. 显式保留了低分辨率紧凑建模与高分辨率回注的逻辑。
3. Gaussian 参数具有一定可解释性。
4. 当前参数量小，便于快速短训和多轮试验。
5. 适合做模块替换与后续消融。

#### 局限

1. 当前仍是轻量骨架，不代表最终模型容量。
2. 频率特征仍偏手工显式描述，后续可能需要更强的学习式频率建模。
3. 目前没有多任务条件控制，也没有多数据集联合采样。
4. 目前模板只适用于同分辨率配对复原，不适用于 LR/HR 尺寸不一致的超分辨率训练。
5. 当前还没有完成系统性的模块消融和大规模评测。

## 四、当前训练模板与训练范式

### 4.1 当前训练模板：T01

当前训练模板正式命名为 `T01`，它是 `V1` 架构下的第一版通用训练模板。其核心特点是：

1. 一次训练只使用一个配对数据集。
2. 支持全图训练或 patch 训练。
3. 支持训练/验证/测试路径独立配置。
4. 支持自动归档代码快照、配置、日志、指标和 checkpoint。

### 4.2 数据读取方式

当前 `PairedImageDataset` 的行为是：

1. 通过文件名或 stem 将 input 和 target 配对。
2. 读取 RGB 图像。
3. 训练时使用同步随机裁剪与翻转增强。
4. 验证时使用同步中心裁剪。

这意味着当前模板天然适合：

- 低照度增强
- 去雾
- 去模糊
- 去雨

但不直接适合：

- LR/HR 异尺寸超分辨率

因为当前 loader 会把 input 和 target 裁到共同最小尺寸，这不符合真正的 SR 设置。

### 4.3 当前默认训练损失与指标

当前训练损失采用：

```text
loss_total = charbonnier_weight * Charbonnier
           + gradient_weight * GradientL1
```

当前默认权重为：

- `charbonnier_weight = 1.0`
- `gradient_weight = 0.05`

这体现出当前训练目标既关注像素级重建，也给边缘梯度一致性一定约束。

主要评估指标为：

- `PSNR`

### 4.4 当前验证与测试纪律

当前项目已经形成比较明确的评估纪律：

1. 训练时的 internal validation 从官方 train split 中切出固定子集。
2. 官方 test split 保留到训练后做正式评估。
3. 不把 test split 用作调参依据。

这对后续论文实验的可信性非常重要。

## 六、当前实验进展时间线

## 6.1 总体阶段判断

当前项目已经从“方向定义与代码骨架搭建阶段”进入到“`V1/T01` 短训可行性验证阶段”。

这意味着当前我们已经完成了：

1. 研究方向正式确立。
2. 可执行模型 `V1` 搭建完成。
3. 训练模板 `T01` 建立完成。
4. 至少一条成功闭环训练 `A01`。
5. 一条跨任务尝试 `A02`。
6. 一条修正后的有效跨任务训练 `A_a02`。

### 6.2 A01：第一条完整闭环训练

#### 任务与目的

- 运行标识：`V1/T01/A01`
- 数据集：`UHD-LL_down4`
- 目标：验证模型、数据管线、日志、验证和 checkpoint 机制是否能真正跑通

#### 主要配置

- 训练方式：全图训练
- 图像尺寸：`540x960`
- batch size：`28`
- 最大步数：`4300`
- 时长上限：`62` 分钟
- 验证间隔：`200`
- checkpoint 间隔：`200`

#### 结果

`A01` 成功完成训练，关键结果如下：

```text
final_step = 4300
final_elapsed_minutes = 59.3975
final official test PSNR = 25.7391
```

训练过程中的 10-batch validation 看起来在 `step=1800` 最好，但后验全量评估表明：

- `final.pt` 在 full internal val 上优于 `step_001800.pt`
- `final.pt` 在 official test 上也优于 `step_001800.pt`

具体地：

```text
step_001800 official-test PSNR = 24.8208
final official-test PSNR = 25.7391
```

提升约为：

```text
+0.9183 dB
```

#### A01 的核心结论

1. `V1` 架构可以在真实配对数据上端到端训练。
2. `T01` 训练模板是有效的。
3. 当前版本的代码、日志、checkpoint、评估流程都已闭环。
4. 训练时只用 `10` 个验证 batch 的做法太噪，后续 checkpoint 选择不能继续只依赖这种弱验证。

### 6.3 A02：第一次跨任务去雾尝试

#### 任务与目的

- 运行标识：`V1/T01/A02`
- 数据集：`UHD_haze`
- 目标：验证同一套 `V1/T01` 是否能从低照度任务迁移到 UHD 去雾任务

#### 主要配置

- 训练方式：`512x512` patch 训练
- batch size：`56`
- 最大步数：`3400`
- 时长上限：`58` 分钟
- 验证间隔：`500`
- checkpoint 间隔：`500`

#### 启动窗口观测

`A02` 没有 OOM，GPU 显存占用接近 `93GB`，说明从显存角度看配置是“能装下”的。

但真实训练表现为：

```text
step 1   elapsed 0.4214 min
step 10  elapsed 1.9732 min
step 20  elapsed 3.7640 min
step 30  elapsed 5.2063 min
gpu_memory_used about 93295 MiB
```

#### A02 中止原因

`A02` 最终在 startup window 被主动停止。原因不是模型不稳定，而是：

1. 真实 step 时间被 4K JPEG 解码和 DataLoader 吞吐拖慢。
2. 原始 smoke calibration 只统计了 GPU compute 时间，低估了端到端真实耗时。
3. 按当前速度，在 `58` 分钟上限内很可能连第一次 validation/checkpoint 都到不了。

#### A02 的核心结论

1. 问题不在模型 trainability，而在数据管线吞吐。
2. 高显存占用不等于有效训练。
3. UHD 数据实验必须把 data-inclusive step time 纳入 smoke 校准。

### 8.1 UHD_haze 数据管线吞吐

### 8.2 A_a02 结果尚未形成正式分析报告

- 尚未形成正式结论文档

### 8.3 当前模板不适用于 SR 主线实验

`4K` 和 `8K` 数据已经验收，但当前 `T01` 只适合同分辨率配对复原任务，不适合 LR/HR 异尺寸的超分辨率训练。因此：
